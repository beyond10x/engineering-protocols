## Outcome

The assertion collection's ESS contracts (`ess/` and `ess/providers/`) and CI move from ESS 0.55.0 to ESS 0.59.0, the newest release (https://github.com/beyond10x/ess/releases/tag/0.59.0). Today `ess` 0.59.0 fails `crates/canon-engineering-assertions/tests/ess_contract.rs`: both `ess-inputs.yaml` declare `requires: ess 0.55.0`, and `--strict-requires` refuses a newer release.

## Scope

Read 2026-10-13 by running the test's `ess` commands with 0.59.0 on `a51a581` and on a copy with `requires: ess 0.59.0`. Each line is cited.

- `ess/ess-inputs.yaml:2`, `ess/providers/ess-inputs.yaml:2`: `requires: ess 0.59.0` (cited: with 0.55.0 there, `specify validate --strict-requires` and `generate types --strict-requires` exit 1; with 0.59.0, validate, compile, synthesize (0 refusals) and both `generate types` exit 0)
- `crates/canon-engineering-assertions/generated/{Cargo.toml,types.rs,types-report.json}` and `crates/assertion-providers/generated/{Cargo.toml,types.rs,types-report.json}`: regenerated by 0.59.0; the drift is the `@generated by ESS` header, `generator_version`, the `serde_json` feature form in the generated `Cargo.toml` (0.59.0 moves `arbitrary_precision` into a default-on `exact-numbers` feature in the providers contract and drops it from the gates contract) and, in the providers report, the `rust_exact_numbers` rule text. `source.schema.json` is byte-identical (cited). The generated `Cargo.toml` files are excluded from the workspace (`Cargo.toml:4`); both host crates include `types.rs` through `#[path]` and enable `serde_json/arbitrary_precision` in their own manifests (`crates/canon-engineering-assertions/Cargo.toml:18`, `crates/assertion-providers/Cargo.toml:13`), so number handling does not change (cited)
- `.github/workflows/check.yml:51`: `ESS_VERSION: "0.59.0"` (cited)
- `crates/canon-engineering-assertions/tests/ess_contract.rs:110` (the panic text naming 0.55.0), `crates/assertion-providers/src/lib.rs:9`, `crates/assertion-providers/README.md:75`, `AGENTS.md:125` (cited)
- `CHANGELOG.md` `[Unreleased]` (cited)

## Protocol first

No protocol changes behaviour; exempt. The `ess_contract` tests are the red: on the commit that moves `requires` alone, they fail on the generated-contract drift.
