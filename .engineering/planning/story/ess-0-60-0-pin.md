## Outcome

The assertion collection's ESS contracts (`ess/` and `ess/providers/`) and CI move from ESS 0.59.0 to ESS 0.60.0 (https://github.com/beyond10x/ess/releases/tag/0.60.0). ESS 0.60.0 refuses `requires: ess 0.59.0` under `--strict-requires`, which `crates/canon-engineering-assertions/tests/ess_contract.rs` passes.

## Scope

- `ess/ess-inputs.yaml:2`, `ess/providers/ess-inputs.yaml:2`: `requires: ess 0.60.0`
- `crates/canon-engineering-assertions/generated/{types.rs,types-report.json}`, `crates/assertion-providers/generated/{types.rs,types-report.json}`: regenerated by 0.60.0; only the `@generated by ESS` header and `generator_version` change, `Cargo.toml` and `source.schema.json` are byte-identical
- `.github/workflows/check.yml`: `ESS_VERSION` 0.60.0 and its release checksum
- `crates/canon-engineering-assertions/tests/ess_contract.rs`, `crates/assertion-providers/src/lib.rs`, `crates/assertion-providers/README.md`, `AGENTS.md`: name 0.60.0

## Protocol first

No protocol changes behaviour; exempt. The `ess_contract` tests are the check.

## Acceptance

1. With `ess` 0.60.0 first on PATH, `cargo test -p b10x-canon-engineering-assertions --locked --test ess_contract` passes: both contracts validate under `--strict-requires`, compile, synthesize with 0 refusals, and their generated types match the committed files byte for byte.
2. The pull request's `check` run installs ESS 0.60.0 and is green.
